## 1. 为什么要补数据

qlib 官方 `cn_data` 的时间范围是 **1999-11-10 → 2020-09-25**，之后没有数据。
（`Quant/data/qlib_data/cn_data` 是 Windows 本地副本，与 WSL 的
`/home/yui/Quant/data/qlib_data/cn_data` 是同一份目录；目录内那个 187 MB 的
`20260914165120_qlib_data_cn_1d_latest.zip` 解包后 `calendars/day.txt` 为
54373 字节、4943 天，与已解压内容完全一致——即 qlib 官方预构建包本身就止于
2020-09-25，无法通过重新下载获得更近的数据。）

对**协方差谱去噪**这一研究而言这是硬伤：协方差结构是强 regime 依赖的，
只有到 2020 就等于完整错过 2021 抱团股瓦解、2024 微盘流动性危机——
恰恰是横截面相关结构最有信息量的两段。

因此必须自建 2020 年之后的数据，并尽量向前衔接成一条连续面板。

## 2. 数据源选型：为什么最终用腾讯

按可行性逐一排除（全部为实测，非推测）：

| 源 | 结果 | 说明 |
|---|---|---|
| **东财** `stock_zh_a_hist` / `spot_em` / `push2his` | ❌ **全域被封** | 整个 eastmoney 域返回 `RemoteDisconnected`，含与本任务无关的端点。系短时间内大量请求触发限流封禁（本机网络正常：同期新浪、腾讯均可用） |
| 新浪 `stock_zh_a_daily` | ⚠️ 可用但不足 | **缺科创板**（`688` 全部缺失）；且仅有前复权口径 |
| **腾讯** `newfqkline/get` | ✅ **采用** | 长历史（沪市主板可回溯至 1991）、**含已退市股票**、含科创板/创业板、**提供不复权与前复权双口径** |

腾讯的三个关键优势正好补上新浪的三个短板。

### 2.1 腾讯端点的技术细节

```
https://proxy.finance.qq.com/ifzqgtimg/appstock/app/newfqkline/get
  ?param=<symbol>,day,<start>,<end>,<count>,<adjust>
```

- **单次请求最多返回 2000 行**。`count > 2000` 返回 `{"msg":"param error","data":[]}`。
  因此采用**向前翻页**：每次取最后 ≤2000 行，再把 `end` 设为本页最早日期的前一天。
  实测 `sz000009` 用 5 页拼出 8416 行完整历史，无缺口无重复。
- **akshare 的 `stock_zh_a_hist_tx` 不可直接用于批量下载**：其实现
  （`stock_hist_tx.py` 第 75–81 行）**按年循环**发请求，每只股票约 37 次
  请求，实测 **18.9 秒/只**，全量需约 9 小时。另有 `get_tx_start_year()`
  额外请求。本实现改为分页，每只约 5–9 次请求，实测约 2.7 秒/只。

### 2.2 字段语义（已用 `qt` 当期快照交叉验证）

行结构：
```
[date, open, close, high, low, volume, {}, turnover, amount, 0, 0]
        [1]   [2]    [3]  [4]    [5]          [7]       [8]
```

⚠️ **注意 `close` 在 `high`/`low` 之前**，与常见 OHLC 顺序不同。验证方式：
`sz000009` 2026-09-30 行 `[2]='6.93'`，而快照 `qt[3]`（最新价）`= '6.93'`，
`qt[5]`（收盘）`= '6.88'` 对应 `[1]`（开盘）——确认 `[1]=open, [2]=close`。

| 字段 | 单位换算 |
|---|---|
| `volume` | **手** → ×100 得股（**科创板 `sh688` 与指数已是股，不乘**） |
| `turnover` | 百分数 → ÷100 |
| `amount` | **万元** → ×10000 得元 |

换算自洽性验证：`sh600000` 2026-09-30 `volume=1,474,848` 手 = 147,484,800 股，
`amount=1.386e9` 元，147M × 9.4 元 ≈ 13.9 亿元 ✅

## 3. 复权口径的关键结论

**腾讯端点在 `adjust=""` 时返回的是不复权价。** 验证方法：用 qlib 的
`$factor` 字段反推 `raw_close = $close / $factor`，与腾讯逐日比对：

```
600000  2020-09-25   tx=9.47   qlib_close=7.414  qlib_factor=0.782901  qlib_raw=9.470  ✅
000009  2020-09-25   tx=6.82   qlib_close=5.539  qlib_factor=0.811017  qlib_raw=6.83   ✅
```

（注意：`|tx - qlib_raw|` 的中位数看起来很大，早期价格差异所致；判定依据是
**末行逐日精确对齐**。）

### 3.1 但两个口径都不可单独信任

**缺陷 1 — 前复权对老股过度调整，出现负价格。**

```
sh600295  2007-04-11  open=-0.86  close=-0.94   r=-0.61
          2007-04-13  open=-0.05  close=-0.32   r=+1.00
          2007-04-19  r=-3.60
```

| 窗口 | 非正价格占比 |
|---|---|
| 1990–2014 | **12.78%** |
| 2015–2020 | 0.363% |
| 2021–2026 | **0.007%** |
| 2022 年起 | **0.000%** |

全样本 550,660 / 8,474,316 行（6.5%），涉及 **559 / 1725 只**（32.4%）。
最严重的 `sh600809` 有 5203 / 7680 行价格 ≤ 0。负价格上做 `pct_change()`
必然爆炸——这是前复权口径出现 91,158 个 \|ret\|>30% 的根因。

**缺陷 2 — 不复权含拆股跳空，且无法用复权因子识别。**

`sh600601` 1991-03-11 约 5:1 拆股（价格 53.10 → 10.60），产生 -80% 跳空，
而**当天复权因子无变化**。实测：不复权收益 < -15% 的下跌中，伴随复权因子
变化的 **0 次**。=> 只能靠"是否超过涨跌幅上限"这一物理约束判定。

### 3.2 解决方案：阶梯式收益

| 优先级 | 口径 | 条件 |
|---|---|---|
| 1 | `q` 前复权 | 当日与前一日收盘均 > 0，且 \|ret\| ≤ 涨跌幅上限 |
| 2 | `r` 不复权 | 前复权不可用，不复权有效且 \|ret\| ≤ 上限 |
| 3 | `x` 剔除 | 两者都异常 → 置 NaN 并标记，**绝不猜测** |

效果：

| | 单一口径 | 阶梯式 |
|---|---|---|
| \|ret\| > 0.30 | 3,712 | **0** |
| \|ret\| > 0.50 | 927 | **0** |
| 左尾 q0.0001 | -0.650 | **-0.150** |
| 右尾 q0.9999 | +0.515 | **+0.199** |

**复权因子仍显式落盘**（v1 面板中的 `adj_factor`），使任何一天都能在对数收益上
加回分红跳空而无需重下数据。

⚠️ **已知限制**：腾讯对部分老股的 qfq 序列起点晚于不复权（如 `000009`
不复权自 1991-06-25，qfq 仅自 1994-04-04），早期无法构造复权因子。

### ⚠️ 两个必须知道的坑

**坑 1：`instrument` 必须按字符串读。**

```python
pd.read_csv(fp, dtype={"instrument": str})     # 或读列名后 .astype(str).str.zfill(6)
```

否则 pandas 会把 `000005` 推断成整数 `5`，使 `000005` 与 `000051` 被合并成
同一只股票，产生完全虚假的收益率序列。

> 这个坑真实发生过：v1 面板（`data_tx/panel/`）就是因为它而作废并被删除，
> `adj_factor` 表的标的数从 101 被错误地缩到 97。

**坑 2：读 `ret_source.csv.gz` 必须 `low_memory=False`。**
否则分块类型推断会抛 `IndexError: list index out of range`。

两个坑都已在 `qr_data.py` 中处理——**下游一律用 `qr_data.load_returns()`**。
